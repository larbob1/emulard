# Raw descriptor ownership

The pinned baseline keeps a global map keyed by the memory address of the host descriptor heap. If a heap is destroyed and a later heap occupies the same address, a stale entry may supply a descriptor run that the new heap never allocated. The patch stores the raw descriptor run in the actual heap's mutex-protected state instead, so its lifetime matches that of the descriptor heap. This also removes accumulation of dead heap keys. The first reservation initializes the whole run with null UAVs, then installs views for known copies. Later calls only install new views. The lock order is the existing global memory registry, then the heap's raw-run lock, then its ordinary slot locks. No reverse acquisition is introduced.

The shared page directory remains append-only and globally visible; this change does not solve its concurrent publication, freed title-memory reuse, or cross-heap descriptor freshness. A new directory entry may still refer to a null descriptor in another heap until that heap is prepared. Initializing those slots avoids undefined descriptor contents, not lost accesses. The candidate is enabled in both builds and has four source transformation tests. The actual hardware lifetime behavior and performance remain unverified.

The last fully successful compile before this revision is b2f6740, including baseline and page-safe configurations.
