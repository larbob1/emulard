# Split-wave synchronization and benchmark comparison

Translator-inserted group meetings now always include a rendezvous, even if the guest barrier diagnostic switch is set to fence-only. That switch still controls guest barriers, but cannot disable synchronization required to emulate a split wave. Groups containing several console waves and branches are conservatively rejected when the candidate needs cross-wave group meetings or split LDS ordering. A scalar branch may be uniform within one console wave and still disagree between waves. This restriction does not establish barrier safety in every single-wave loop. Group-uniform control-flow analysis is a remaining prerequisite for widening this coverage.

The single-host-wave path now uses logical base zero without an extra shared-memory counter or rendezvous. Larger groups initialize their counter atomically. Compute split-wave translations also reject shared-memory allocations exceeding the host limit. The existing wave-tail regression suite includes a new policy test.

The local frame report accepts an optional baseline log: python tools/frame_report.py candidate.log --baseline baseline.log --skip 5. It reports numerical interval medians and changes in frame time, copy-back volume and dropped draws. A clean target interval requires at most 100 ms per frame, no reported dropped draws and no reported pipelines being made. This is not a proof of correct graphics or sustained per-frame latency. Compare matching scenes and settings. Logs remain local; only numerical summaries are printed.

Keep the all-or-none builder gate and full writeback fallback until coverage and correctness are measured.
