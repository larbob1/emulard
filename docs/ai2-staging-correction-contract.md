## B. Publication separately (no production policy yet)

Existing Last.hash/asked/partial can be written before detile returns, dirty before iterating, judged/detiled before successful subresource completion. #102 actual controlled invalid pitch reproduces partial bytes and dirty, not ordinary reachability. Staging::upload records copies based on dirty/uploaded before refresh and its deferred callback clears dirty/sets uploaded; on-demand deferred callback reads detiled. Merely returning Result or moving dirty to end is insufficient: a previously recorded list may already name the same staging bytes, and partial data may still be submitted. Never mutate in-flight backing or mark a texture successfully uploaded just because an upload was recorded. AI1 owns actual submit policy.

Proposed two stages: validate immutable footprints, layout/mip/slice/pitch/source length, destination extents and held-level plan BEFORE any in-place writes (share checked Layout::walk prerequisites rather than duplicate unchecked assumptions). If every remaining operation is proven infallible and all relevant ownership/guard conditions hold, commit can write in-place with no whole-texture extra allocation. Otherwise use bounded private output and commit only after every intended subresource succeeds; no unconditional full texture clone or unbounded scratch, no silent skip for large textures. Any uncertain outcome must refuse before execution or follow explicitly reviewed invalid/retry path; do not substitute stale/zero contents as correct. For valid previous staging, preserve bytes and published hash/validity/judgement/dirty upon refusal; separately mark retry eligibility, reset asked/partial throttle as necessary without erasing proof of prior valid generation. First-fill failure has no valid generation; block dependent upload or fail safely according to AI1 submission policy. Valid all-zero capture is not absence; independently established holes may be zeroed only with coherent coverage (#80), unknown read failure is not hole. On success publish metadata only after actual bytes succeed, under established staging serialization and mapping-generation guard. Separate recording-time dirty/uploaded state from actual confirmed execution. Old valid bytes retained is memory preservation, not proof that they satisfy current sampling.

Lock-order review: Staging::last held through refresh_timed/unlocked; judgement calls descriptor registry; committed/mapping guard ordering must preserve existing contract and #32 review. Prepared opt-in short_snapshot releases mapping guard then checks epoch before/after detile; after-check alone cannot undo published stale bytes; disable in proposed narrow route only if explicitly chosen by AI1/AI3/AI4, not a permanent fix. No new lock nesting or epoch assumption approved. Require coherent capture and publication exclusion separately from GPU ownership.
