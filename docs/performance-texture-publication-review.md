# P11 texture short-lock publication review

Frozen #18 base dbac4c6, existing opt-in VICTORY_TEXTURE_SHORT_LOCK only. The existing short snapshot checks the global mapping epoch after hashing but before detile, and checks again after detile. detile sets dirty and mutates staging; a post-publication retry is not a transactional rollback. Proposal reacquires the established read guard without waiting after hashing, then compares epoch under that guard, rejects contention or changed mapping without assigning hash or modifying staging, and retains the guard through existing publication. Existing asked reset and later retry preserved. No new waits, callbacks or flags; still holds the existing per-Staging last mutex. Hashing remains outside mapping lock; changed texture detile no longer does, so potential lock savings are smaller. This does NOT prove freshness against independent CPU, GPU or DirectStorage writers, eliminate existing partial-detile behavior, guarantee upload ordering, solve epoch wrap, or improve FPS. Existing baseline unchanged. Requires AI2 staging/lock review and native race fixtures before any runtime application. A read-only exact preview and tests verify anchors and source ordering, not concurrency behavior. No game data used.
